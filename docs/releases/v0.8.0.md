## Codex Auto Retry v0.8.0

### Reset-Aware Quota Recovery

- Tasks that fail on a usage-limit wall (5-hour or weekly windows) now wait for the server-reported reset time instead of blind retrying, then resume the exact original thread via the app-server IPC channel.
- Quota evidence is tracked per limit: subscription windows (`codex`) and purchased credits (`premium`) update their own evidence space only, so one cannot pollute the other. A window note that already established a recovery wait is never re-credited (ADR-0003).
- When several windows are exhausted, recovery waits on the one with the latest reset time. Waking uses an absolute-epoch comparison, so sleep or hibernate cannot overshoot the reset.
- At reset time exactly one queued thread resumes first; only verified progress releases the rest of the window's queue. A re-limit parks the window on the new reset time.
- Walls automation cannot cross — depleted credits, spend caps, billing/auth failures, or untrustworthy reset times — park the task in a distinct Needs Attention state instead of retrying forever. Quota recovery is exempt from the 30-minute circuit breaker.

### Desktop Client

- New Wails desktop client: a disposable viewer/controller for the watchdog. Closing it exits only the client; the watchdog and tray keep running (ADR-0004).
- Live snapshot dashboard: task queue, countdowns, retry-now/cancel controls, global pause, and account quota at a glance.
- Simplified Chinese and English with a live language switch covering dynamic strings; themes persist across restarts.
- Embedded icon and DPI manifest; cross-platform tray icon with a state-tinted retry arc and system notifications via beeep.

### Conversations

- The desktop client can browse past Codex sessions: real conversation titles, per-project-directory filtering, and multi-segment stitching of split session files.
- Queue rows deep-link to the underlying conversation via the rollout `root_id`.
- Conversation reads go through a whitelisted catalog and an incremental JSONL projection; conversation content never leaves the machine.

### Management API

- Every client reads through one localhost HTTP surface (`127.0.0.1`, per-launch token discovered via `api.json`). The snapshot shape is locked by a contract test and golden file.
- New endpoints: conversation list, conversation detail pagination, and the account quota contract. All responses send `Cache-Control: no-store`.

### Platform

- Linux and macOS build with monitor-first capability seams; on Unix the supervised worker detaches into its own session.
- Domain code moved to `scripts/source/internal/watchdog` with a thin `cmd/auto-resume` entrypoint; duplicated PowerShell helpers consolidated into shared modules.

### Installation

Download and extract `Codex-Auto-Retry-0.8.0-windows-x64.zip`, then run `安装.cmd`.
The package includes the startup manager, safe launcher and emergency-disable tools. No Go or Node.js installation is required.

Shared-backend mode remains opt-in, and the installer never publishes a global `CODEX_APP_SERVER_WS_URL` route. Existing retry settings are retained.

Regression coverage includes the management API snapshot contract, quota evidence spaces, probe dispatch caps, conversation catalog and projection, i18n, and the existing installer/rollback suites. Real provider availability and a full reboot remain outside automated release validation.
